# WA Citizen Benchmark (WA-20)

This bucket measures how useful Civic Agent is to Washington residents. It is a coverage-growth instrument, not only a quality check: the suite deliberately includes questions the system cannot answer yet, and the headline metric is the distribution of achieved answer modes over time (`unsupported_with_path` -> `partial` -> `exact`) plus quality within mode.

Design provenance: `docs/goals/2026-07-13-benchmark-driven-launch-goal.md` (Appendix A/B), including the adversarial methodology review whose rules are binding here.

## Files

- `cases.json`: the 20 cases. Contract enforced by `tests/test_wa_citizen_benchmark_contract.py`.
- `expectation-log.md`: append-only log of every expectation change with justification. The ratchet check reads it.
- `scoreboard.md`: generated by the Tier 0 scorer (`python3 scripts/wa20.py`). Do not hand-edit.
- `runs/`: Tier 1 answer-capture runs, one dated directory per run (runner lands in milestone M4).

## Case Schema

Immutable identity block (never edited after merge):

- `id`, `question`, `paraphrases`, `persona`, `altitude` (`state|county|city|school_district|special_district|multi`), `jurisdiction`, `archetype`, `difficulty` (`T1_lookup|T2_composition|T3_interpretation`), `anchor`.

Versioned expectation block (edited only via the ratchet, logged in `expectation-log.md`):

- `expected_answer_mode`, `expected_failure_mode`, `expected_source_ids`, `expected_missing_sources`, `expected_facts` (`{id, value, tolerance, unit, description, reproduction_ref}` - machine-checkable), `required_caveats` (`{id, pattern, description}` - `pattern` is a case-insensitive regex the Tier 1 scorer greps in answers), `improvement_path`, `unlocked_by`, optional `max_data_age_days`.

Tier 0 machinery:

- `required_claims`: `{jurisdiction, category, role}` resolved against source-card `coverage_claims`. `role` is `core` (the question is unanswerable without it) or `adjunct` (missing one caps the case at `partial`). `category` is an active taxonomy key from `docs/coverage-taxonomy.md`, or a `proposed:<family>.<category>` key for data families not yet promoted - a probe that promotes the category and adds card claims flips the case without editing it.
- `mode_ceiling`: the best mode this case can ever reach (T3 why-questions and parcel-dependent math cap at `partial` honestly).

## Rules (binding, from the methodology review)

1. Question text is immutable. Fixing a question means retiring the case id and adding a new one.
2. One-way ratchet: `expected_answer_mode` may only move up the rank `unsupported_with_path (0) -> needs_refresh/side_by_side_only (1) -> partial (2) -> exact (3)`. Downgrades require an `expectation-log.md` entry naming the case and the reason; the ratchet check fails otherwise.
3. Never headline a mean score. Report per-case win/tie/loss and mode distribution. Claim improvement only when case flips exceed the measured noise floor (two same-config Tier 1 runs establish it before any improvement claim).
4. Human scoring is confined to `civic_usefulness` on the 5 anchor cases (`anchor: true`), labeled author-scored and unblinded. Target under 90 minutes per Tier 1 run.
5. Paraphrases are never sampled in scored runs; they exist for a robustness bit (same answer mode across phrasings) only.
6. Web-baseline comparisons (Tier 2) are same-day, point-in-time contests. No cross-quarter baseline claims.
7. Fresh annex questions must be sourced verbatim from real residents (feedback links, public comment), not authored by the maintainer.

## Anchor Cases

`seattle-parks-2026-lookup`, `wa-checkbook-vendor-lookup`, `pierce-vs-king-per-resident`, `kc-property-tax-why-up`, `seattle-kc-homelessness-kcrha` - one per stratum: covered lookup, covered-but-hosted-blocked actuals, cross-jurisdiction composition, top-demand uncovered, multi-jurisdiction accountability.

## Divergences From The Goal Appendix

- `kc-cuts-despite-20b` is seeded `partial` (not `side_by_side_only`): the covered frame-discipline half already supports a partial answer; the side-by-side rule is enforced via its `biennial-vs-annual` caveat instead.
- Case ids keep the goal appendix's kebab style so the goal brief's Expected Eval Movement table maps one-to-one.

# First Tier 1 Runs - Findings (2026-07-14)

Two same-config runs (`2026-07-14-run-a`, `2026-07-14-run-b`): 20/20 cases captured each by fresh agents on the repo-skills surface (hosted-path emulation; see run-metadata.json). Mechanical results: run A 6/20 fully passing, run B 4/20. **Noise floor: 9 case/check flips between identical configs** - per the benchmark rules, no improvement claim is real unless it exceeds this.

These are baseline runs. Per-case civic_usefulness (human, 5 anchors) is still open in each run's worksheet.md.

## Classification of recurring failures

### Fixed immediately (benchmark bugs)

- `spd-budget-2020-vs-2026` facts failed in BOTH runs because the seeded values summed every `%POLICE%` department (including the Community Police Commission and Police Relief and Pension) while both captured answers correctly scoped to the Seattle Police Department alone. Facts corrected (see expectation-log 2026-07-14); classic `scorer_gap` caught by the loop's first real run.

### Scorer-vs-contract mismatch (fix the SKILLS, keep the scorer strict)

- `source:<card-id>` checks failed across many cases (seattle-parks, spd, pierce-vs-king, kcrha, jumpstart, kc-cuts; kc-sheriff in run B) because answers cite dataset names/ids ("Socrata 8u2j-imqx", "Open Budget Dashboard snapshot") instead of the source CARD id (`seattle.operating_budget`). The Pierce and DOR skills mandate card ids in traces; the older Seattle/King County/Washington skill trace templates do not. **Follow-up: tighten the older skills' trace templates to require the card id.** The scorer should stay strict - the card id is the citation contract.

### Expectation-calibration questions (human decision needed)

- `wa-checkbook-vendor-lookup`: expected `exact`, both runs declared `partial` - arguably HONEST on the hosted-emulation surface, where vendor answers come from the top-100 truncated aggregates. Decide: either the expectation becomes surface-dependent (hosted: partial / local-DB: exact) or `exact` stands only for the canonical local path. A downgrade needs an expectation-log justification.
- `wa-new-taxes-actually-collecting`: expected `needs_refresh`, both runs declared `partial` - agents answered from the stale revenue snapshot with data-through caveats instead of refusing on freshness. The skill may need an explicit staleness rule ("if data-through is older than N days for current-period questions, declare needs_refresh").
- `spokane-police-vs-housing`, `kc-actuals-vs-budget-trap` (both runs), `evergreen-schools-cuts` / `pierce-vs-king-per-resident` / `seattle-parks` (one run each): mode declarations off by one rank in either direction. Mode-declaration discipline is the single biggest mechanical failure class - worth a router rule stating the five modes must be declared verbatim with definitions restated.

### Possible answer gaps OR too-narrow caveat regexes (read the answers before deciding)

- `st3-gap-out-of-scope` (both runs), `fragmentation-is-the-answer` + `no-outcome-claims` (both runs, KCRHA case), `modeling-choices-explicit` (both runs), `causation-is-interpretation` (both runs, SPS case). Each failed twice, so these are systematic: either the answers genuinely omit required content (a skill gap - the caveats exist in benchmark cases but NOT yet as skill-level answer rules for these composed questions) or the regexes are too narrow for legitimate phrasings. The human worksheet pass should decide per caveat.

## What went RIGHT (worth saying)

- Zero fabrication observed in spot reads: uncovered halves were refused with paths.
- The hosted checkbook aggregates path (M3) worked: vendor answers cited the checked-in aggregates with truncation caveats instead of dead-ending.
- Numeric facts: after the SPD correction, every remaining fact check passes in run A except the pierce-vs-king population flips in run B (agent cited different denominator framing) - the 0.05% relative-floor design held.
- Validation checks in traces were near-universal; agents consistently reproduced the skills' known totals.

## Run C (2026-07-14, after the fix batch)

Same capture config as A/B, after: source-card-id trace mandate, router Freshness Posture rule, revenue snapshot refresh (2026-05), and the wa-new-taxes calibration. **9/20 fully passing (A: 6, B: 4).** A->C: 13 flips, 9 favorable vs 4 unfavorable - at the edge of the 9-flip same-config noise floor, but the targeted checks moved deterministically where aimed:

- **Source-card-id failures halved (9 -> 4)** and every remaining one is a composed case citing one card but not the second (e.g. budget but not checkbook for Pierce). The mandate works; composed-answer discipline is the residue.
- **wa-new-taxes now passes clean** - the agent gave the refreshed May-boundary answer with publication-lag language and declared partial, matching the recalibrated expectation. The freshness posture behaves as designed.
- **Answer-mode disagreements are now the dominant failure class and did NOT improve** (5 -> 6): the persistent calibration cases (wa-checkbook exact-vs-partial on the truncated hosted path; spokane, sound-transit, kc-actuals partial-vs-mode-choice) plus a NEW thoughtful one - the run C kc-sheriff agent declared partial because the question asks "positions" and the source carries budgeted FTE, which is arguably more honest than the expected exact. These are judgment calls for the maintainer, not agent errors.
- **New finding: denominator discipline.** The run C pierce-vs-king agent missed both OFM population facts - likely using FIT's GovernmentMetrics population (FIT rows carry fit_population) instead of the OFM denominator the recipes mandate. The FIT skill section should state the wall explicitly: fit_population is context, never a Scale denominator.
- Composed-question caveat patterns (KCRHA fragmentation/outcomes, deficit modeling-choices, ST3 out-of-scope) remain systematically unmet - these caveats exist in benchmark cases but not as skill-level answer rules; that is the next skill-contract gap after mode discipline.

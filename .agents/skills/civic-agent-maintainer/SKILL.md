# Civic Agent Maintainer

This skill maintains the Civic Agent repo and plugin packaging. It is not the budget-answering skill.

Use `@civic-agent` or `@civic-agent-dev` for civic budget questions. Use this maintainer skill when the user asks to refresh, install, verify, package, smoke test, or inspect Civic Agent development state.

## Primary Workflows

### Refresh the local dev plugin

When the user says something like:

- "refresh Civic Agent dev"
- "update the dev plugin"
- "make the new source available in @civic-agent-dev"
- "is King County ready in the dev plugin?"

Run:

```bash
python3 scripts/dev.py install
```

Then report whether the install succeeded and repeat the final instruction from the script: open a new Codex thread and explicitly invoke `@civic-agent-dev`.

### Inspect status

When the user asks what is installed, stale, current, or ready:

```bash
python3 scripts/dev.py status
```

Summarize the four states separately:

- canonical jurisdiction files under `jurisdictions/`
- checked-in production package under `plugins/civic-agent/`
- installed production cache for `@civic-agent`
- installed dev cache for `@civic-agent-dev`

### Verify freshness

When the user asks whether the repo or dev install is fresh:

```bash
python3 scripts/dev.py verify
```

If verification fails, explain the failing layer and the next action. Do not imply that an active thread has reloaded the plugin; a fresh thread is still required after install.

### Smoke test

When the user asks for smoke prompts or a quick readiness check:

```bash
python3 scripts/dev.py smoke
```

Report the prompts it prints. The actual `@civic-agent-dev` question should be run in a fresh thread after install.

### Package check

When the user asks only about checked-in production package drift:

```bash
python3 scripts/package_plugin.py --check
```

If stale generated references are reported, refresh with `python3 scripts/package_plugin.py` unless the user explicitly asked for a read-only check.

### Validate source data

When the user asks whether sources, snapshots, fingerprints, or managed data are ready:

```bash
python3 scripts/source_data.py --json validate --all
```

For one source:

```bash
python3 scripts/source_data.py --json validate <source_id>
```

Use `--refresh-check` only when the user is explicitly asking whether an official source may have drifted. Default validation is offline: it checks source fingerprints, checked-in snapshots, and existing managed local databases without downloading data. A managed local source can validly report `missing`; if the user wants to answer from it, run `ensure` or `refresh` for that source.

## Rules

- Keep `jurisdictions/` and `skills/civic-agent/` as the canonical source.
- Do not hand-edit `.generated/`; it is regenerated by `scripts/dev.py install`.
- Do not hand-maintain a second dev router skill in the repo.
- Do not use `@civic-agent-dev` for generic budget questions unless the user explicitly asks to test local development behavior.
- Never claim the current thread has loaded a newly installed plugin. Tell the user to open a new thread for `@civic-agent-dev` smoke tests.
- Do not imply validation audits every row or changes answer routing. Validation checks readiness; normal answers still use the source card's storage policy.
